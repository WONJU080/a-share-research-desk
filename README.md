# A股研究台

一个按需执行的 A 股上市公司研究桌面程序。它不会在启动时分析全市场，用户提交研究指令后，程序才会按工作流获取目标股票集合、补充披露文件索引并整理结果。

## 启动

```bash
npm install
npm start
```

## 打包为可点击的 macOS 应用

```bash
npm run dist:mac
```

打包产物会出现在 `release/`，其中的 `.dmg` 可以安装，安装后的 `A股研究台.app` 可像普通 macOS 程序一样双击打开。

Electron 二进制默认从 GitHub 下载，国内网络容易超时。项目中的 `.npmrc` 已将其指向国内镜像：

```ini
electron_mirror=https://npmmirror.com/mirrors/electron/
```

如果手动从环境变量设置，也可以使用：

```bash
export ELECTRON_MIRROR=https://npmmirror.com/mirrors/electron/
```

## 当前版本边界

当前是可运行的工作流原型，界面、按需执行逻辑、结果字段、CSV 导出、“部分缺失”状态和本地持久化缓存已经具备。未配置 AI 时使用本地演示数据；配置 OpenAI 兼容接口后，研究任务由 AI 分析完成。

## AI 接入（中转站兼容）

在「数据源与设置」页面填写：

- `API Base URL`：任意 OpenAI 兼容服务的根地址（如 `https://api.deepseek.com`）
- `API Key`
- `模型名称`
- `最大输出 tokens`（默认 8192，过小会导致长输出被截断）
- `请求超时`（默认 120 秒，推理模型思考时间长）
- `附加参数`（可选，中转站专用字段，以 JSON 传入并合并到请求体，不会覆盖 `model`/`messages`）

程序通过 `GET /models` 获取模型列表，帮助你确认中转站实际提供的模型名（部分中转站未开放该端点时会友好提示，可忽略并直接用已知模型名）。请求和响应均按 OpenAI 标准协议；推理模型会同时读取 `content` 与 `reasoning_content`，`max_tokens`、超时、附加参数均可配置，从而兼容绝大多数中转站的推理模型。

## 业务分析的内容深度

「分析一支股票」默认以**最近一个会计年度的年度报告**为依据产出业务事实，而不是一句话摘要；仅在指令明确写出"近十年 / 多年 / 某一具体年度（如 2024 年年报）"时，才按要求的年度窗口覆盖多年报告。每一家公司的入库结果包含：

- `business`：主营业务详细描述（2–4 句，含指定报告期的产品线概况）
- `products`：主要产品 / 业务 / 技术方向列表
- `facts`：目标报告期的业务事实数组，每条含 `year`、`product`、`description`、`source`（具体披露文件，如"2024年年度报告"）、`confidence`；接入巨潮后另有 `page`（页码）与 `quote`（年报原文句子）

AI 模式下，这些内容由大模型依据其训练语料输出；接入巨潮后，逐份年报实际解析并提取原文。未配置 AI 的演示数据同样携带完整的 `business/products/facts` 结构，保证筛选链路一致。

## 信息源：巨潮资讯网真实年报（按需下载）

「分析一支股票」时，程序会先从**巨潮资讯网**（证监会指定披露平台，`cninfo.com.cn` 半官方接口）拉取该公司年报清单（默认最近一年；指令写明"近十年/多年/某一年"时按对应范围下载），下载年度报告全文 PDF（存储在本地 `userData/reports/<代码>/`），用 `pdfjs-dist` 抽取「公司业务概要 / 经营情况讨论与分析 / 主营业务分行业分产品」章节，再把带页码的原文交给 AI 提取：

- `facts` 每条新增 `page`（如"第21页"）与 `quote`（年报原文句子），**业务描述不再依赖 AI 记忆，而是来自真实披露文件**
- 「相关依据」列优先引用 `quote` 原文，标注年报与页码，可直接回查 PDF 核对
- 每日首次启动时自动检查已缓存公司是否有**新一年年报**（增量补更当年披露），无需重新分析
- 每份年报只下载一次，断点可复用；`reports/manifest.json` 记录下载进度

边界提示：年报覆盖 = 上市以来（澜起科技 2019 年上市，能拿到 2019—最新年报；上市未满 10 年的公司按"上市以来 N 年"处理）。可在「数据源与设置」关闭"接入巨潮真实年报"回到纯 AI 训练知识模式。

报告期由指令控制：默认分析最近一年报告；写明"近十年 / 多年 / 某一具体年度"才扩大窗口。示例：`分析澜起科技近三年的业务`、`分析宁德时代 2024 年年报的主营构成`、`分析5家芯片公司`（默认最近一年）。

## 搜索范围与相关度依据

搜索范围分为「全部股票（含未分析）」与「仅已分析股票」。「仅已分析」模式在信息库内筛选/抓取：本地匹配按关键词命中打分排序，AI 模式则由大模型在信息库范围内抓取并引用库内原文说明相关性。

结果表的「相关依据」列会解释**为什么这家公司排在前列**：

- 本地匹配：逐条给出命中的关键词、它在入库事实中的**原文句子**（截取关键词前后文），并标注具体披露来源（如"2016年年度报告：寄存器时钟驱动器（RCD）等时钟芯片进入全球主流内存模组"）与命中关键词数，可据此核对"业务明确包含 X 的公司"是否真的被正确排序；
- AI 抓取：额外展示 AI 的 `reason` 说明（引用信息库内该公司的逐年事实原文）；
- 关键词匹配可直观看到纪录片/年报中的实际用词，方便你判断当时凭印象的预期是否与程序依据一致。

**AI 调用失败时**：程序会在「执行过程」中标注失败并取消本次分析/筛选，明确提示错误信息，不会静默切换到演示数据。可在「数据源与设置」中测试连接、调整超时/模型名后重试。

「仅已分析股票」范围下的业务筛选在**本地对入库的 `facts/business/products` 逐条比对**（关键词可含数字/字母，如 `5G`、`AI`、`DDR5`，大小写不敏感，按命中打分排序）；配置 AI 时，则把整库入库内容交给 AI、让它**在信息库范围内抓取**与关键词相关的公司（不引入库外股票、不新增分析、不改写缓存）。两种方式均不会把精简摘要当成唯一依据。

## 搜索范围

研究任务页提供一个「本轮搜索范围」开关，选择范围后立即保存，之后每次运行都会生效，也可以直接在指令里说明（例如「在已经分析的股票当中查找…」）临时覆盖：

- `全部股票（含未分析）`：从全市场/指定板块获取股票集合，未分析过的会执行新分析并进入缓存。
- `仅已分析股票`：只在本地已缓存并完成分析的股票中筛选，不会获取或分析新股票。在已分析范围下，即使用户切换到「全部股票」模式执行的分析，也会先落在缓存里，供下次在「仅已分析股票」范围下复用。

## 本地缓存

每次新分析的股票数据会以股票代码为键保存到 Electron 用户数据目录下的 `research-cache.json`，并按公司增量落盘。关闭并重新打开程序后缓存仍然存在；即使任务中途关闭，已经完成落盘的股票也不会丢失。下一次指令涉及相同股票时，程序会跳过已经缓存的股票，只分析新的股票，并在结果中分别标记“已复用”和“本次新分析”。

缓存还会记录分析覆盖范围。目前分为“基础信息”和“业务与财报”：已经缓存基础信息的股票，在再次查询基础信息时可以复用；如果后续要求业务、主营、财报或产品分析，程序不会误把基础信息当成业务分析结果，而会继续补充业务与财报数据。补充完成后，同一股票可以同时拥有两种覆盖范围。

结果列表中每一项都会标注「信息来源」（例如“2025年年度报告”“2024年半年报”）便于溯源，并显示市值（未确认时以“—”占位避免误读）、可信度与「已复用/本次新分析」标记，支持一键导出 CSV。

缓存文件路径由 Electron 的 `app.getPath('userData')` 决定，macOS 通常位于 `~/Library/Application Support/A股研究台/research-cache.json` 附近。生产版本应在缓存记录中增加数据源版本、报告覆盖范围和更新时间，在数据过期时按策略重新获取，而不是永久使用旧行情。

接入生产数据时，只需要替换 `src/main.js` 顶部的数据源适配层，并保留以下数据契约：

- 行情/股票集合：代码、名称、总市值、市场、行业
- 披露文件：报告类型、年度、原始 URL、页码、解析状态
- 业务事实：产品、业务关系、业务状态、时间、证据片段、可信度

推荐后续接入顺序：交易所/巨潮正式披露文件 -> 文档下载与 OCR 队列 -> PostgreSQL + 全文索引 -> 向量检索与证据抽取 -> 人工复核后台。大模型只应基于已经获取的原始证据做抽取和分类。
